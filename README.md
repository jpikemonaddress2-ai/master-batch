# master-batch

マスターバッチ（樹脂に添加剤を指定濃度で練り込む作業）向けの、配合計算と造粒条件記録アプリ。

- **配合計算** — 添加濃度と作成量を入れると、各原料の仕込み量を出す。原料の有効成分%を持つので、既製MB（例: 有効成分50%）を使う場合の換算ミスを防ぐ
- **造粒条件の記録** — サンプル1バッチごとに、狙い値・実秤量・造粒条件・評価結果を記録する
- **検索と比較** — 条件で絞り込み、選んだサンプルを列に並べた転置表で比較する

社内LANの1台で動かすアプリ。Node（v22.16 以降、推奨 v24）の標準モジュールのみを使い、npm 依存はゼロ。

## 起動

`start.bat` をダブルクリックする（または `node server.mjs --open`）。ブラウザで http://localhost:5173 が開く。
データは `data/` フォルダ（`masterbatch.db`）に保存される。

**バックアップ・別PCへの移動は、サーバーを止めてから `data/` フォルダごとコピーする。**
止めるときは Ctrl+C かウィンドウを閉じる（終了時に未反映の記録を `.db` 本体へ書き戻す）。
動いている途中の `.db` だけをコピーすると、直近の記録が `masterbatch.db-wal` 側に残っていて欠けることがある。

社内LANの他のPCから開けるようにするには、`config.mjs` の `HOST` を `'0.0.0.0'` にして再起動し、Windows ファイアウォールでの許可を受ける。
他のPCからは `http://<このPC名>:5173` か `http://<このPCのIPアドレス>:5173` で開く。
社内DNSの完全な名前（例: `pu.example.local`）で開く場合は、`config.mjs` の `EXTRA_HOSTS` の配列にその名前を足す
（外部サイトからの書き込みを防ぐため、知らない名前で来たアクセスは拒否している）。

## 記録の扱い

- サンプル・配合を変更するときは「変更者」の名前を入力する。変更前の内容は履歴に残り、画面の「この変更の内容」で確認できる
- サンプルを削除しても内容は残る（「サンプル一覧」→「削除済みサンプル」）。削除したサンプルの番号は使い回せない
- サンプルが付いた配合は、配合コードと組成を変更できない（「複製」で新しい配合を作る）
- 配合やサンプルで使った原料は、名前・種別・有効成分 % を変更できない（「原料マスタ」で使用停止にして新しく登録する）。グレード・CAS 番号も、入れた後は変更できない（空欄なら後から入れられる）
- 原料の CAS 番号は形とチェックディジットを確かめる（全角で入れても半角にそろえる）。既製 MB は有効成分の番号を入れる。樹脂・混合物は空欄でよい
- 実秤量は入力した小数の桁数のまま記録・表示する（「250.0」を「250」にしない）。この版より前に記録した値は桁数を不明のまま残し、丸めずに出す（別の項目を直して保存しても、桁数を決め直さない）。比較表の差は量で判定する（「250」と「250.0」は差にしない。変更履歴の差分では差として出す）
- 実秤量が一部の行だけのときは、総量も「推定総量」と出す（未入力の行は狙い量で補う。実濃度の「推定」と同じ）
- 新規サンプルの「前回のロットを入れる」は、空欄のロットに、その原料を直近（作成日の新しい順。そのサンプルの作成日まで）のサンプルで使ったロットを入れ、入れた欄に色を付ける。引用や「続けて新規」では、ロットは引き継がない
- 自由項目の単位は、同じ項目名で使われた単位を候補に出す。最も多い単位（単位なしも数える）と違う単位を書くと注意を出す（g/10min と g/10分 のような表記ゆれを減らすため）
- 「サンプル一覧」の測定値の絞り込みは、項目名（完全一致）と下限・上限（両端を含む）で探す。数値として読めない値（n.d. など）は対象外（全角の数字は読む）。単位は区別しないので、単位が複数ある項目では画面に注意を出す。測定条件で値が変わる項目は、項目名に条件を含めると混ざらない（例: MFR(230℃/2.16kg)）
- 使用停止の原料は、配合に新しく組み込めない（新規・複製・原料の追加のどれでも）
- 使用停止の原料を含む配合からは、新しいサンプルを作れない（サンプルのある配合は「複製」して、無い配合はその場で原料を置き換える）。既存のサンプルは直せる
- CSV は3か所から出せる: 「サンプル一覧」（1行1サンプル）、「サンプル記録」（保存済みのそのサンプル1件）、「比較」（画面の比較表のまま、1行1項目）
  - 実濃度の列は数値だけ。未入力の行を狙い量で補った推定値かどうかは「実濃度の区分」（推定 / 実測）に出る
  - 単位がサンプル間で揃わない項目は、値（単位を付けず入力どおり。見出し・単位欄に「単位混在・［単位］列を参照」）と「◯◯［単位］」を別の列（比較の CSV では別の行）に分ける。値があって単位が空のときは「（単位なし）」。差は値と単位を別々に比べる（画面の比較表も同じ）。揃っていれば見出しに単位を付けて1列なので、出すサンプルの範囲によって列の数が変わる（複数の CSV を貼り合わせるときは注意）
  - 比較の CSV は、画面を開いた後に削除されたサンプルを含まない（そのときは画面に件数を出す）

## 状態

MVP（PLAN.md の Step 1〜3）を実装済み。実装方針は [PLAN.md](PLAN.md) を参照。

| ファイル | 役割 |
|---|---|
| `server.mjs` | HTTP サーバー（静的配信と `/api/*`） |
| `db.mjs` | スキーマ（マイグレーション）とクエリ、入力の検証、サンプルの変更履歴 |
| `public/calc.mjs` | 仕込み量・実濃度の計算（画面とサーバーで共用） |
| `public/fields.mjs` | 造粒条件の固定項目の定義（画面とサーバーで共用） |
| `public/matrix.mjs` | 比較表・変更履歴の差分・CSV の展開（画面とサーバーで共用） |
| `public/format.mjs` | 数値の表示書式（画面とサーバーで共用） |
| `guard.mjs` | 外部サイトからの要求を拒否する検査（Host / Origin / Content-Type） |
| `http-util.mjs` | HTTP の小道具（エラー型、URL の id の検証、ダウンロードのファイル名） |
| `public/*.js` | 各タブの画面（recipe / sample / list / compare） |
| `test/` | `node --test` で動く自動テスト |
